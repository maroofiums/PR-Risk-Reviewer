# Python Stack Notes (Django, Django REST Framework, FastAPI, Alembic)

Read this only when the diff contains Python backend code. It sharpens the generic rubric with framework-specific failure modes.

Contents: Django migrations, Django/DRF, FastAPI and Pydantic, Alembic/SQLAlchemy, async pitfalls, ML-serving code.

## Django migrations
- `RunPython` without a `reverse_code`: migration cannot be rolled back. Reversibility High.
- `RemoveField`, `DeleteModel`, `RenameField`, `RenameModel`, `AlterField` changing type: data loss or application breakage during rolling deploys. Data High.
- `AddField` with `null=False` and no `default` on a populated table: fails or locks. Add nullable, backfill, then tighten in a later migration.
- Index creation on a large PostgreSQL table without `AddIndexConcurrently` (and `atomic = False`): long write lock.
- Data migration over the whole table in one transaction: lock and memory risk. Look for batching.
- Squashed or edited existing migrations: applied environments will diverge. Existing migration files should almost never be modified.
- Multiple leaf migrations in one app: merge conflict waiting to happen.
- Model change with no migration file in the diff (or the reverse): flag it.

## Django and Django REST Framework
- `permission_classes` changed, `AllowAny` added, or `authentication_classes = []`: security High.
- `@csrf_exempt` added to a state-changing view.
- Serializer `fields` / `exclude` changes: response shape change (API contract) and possible data exposure (`fields = "__all__"` leaks new columns automatically).
- Queryset changes in views: filtering removed (data leakage across users), `select_related`/`prefetch_related` removed (N+1 performance regression).
- Signals and `save()` overrides: hidden side effects; check bulk operations bypass them.
- Settings: `DEBUG`, `ALLOWED_HOSTS`, `SECRET_KEY`, `CORS_*`, `SECURE_*`, `SESSION_*` changes.
- Pagination or ordering defaults changed: silently changes API results.

## FastAPI and Pydantic
- Changes to `Depends(...)` auth dependencies, or a router included without its dependency: unprotected routes.
- `response_model` removed or loosened: may leak internal fields.
- Pydantic model field changes: required/optional flips, type changes, `extra` config, validators removed. These are API contract changes.
- Pydantic v1 to v2 migration: behavior differences in validation and serialization; treat as High.
- Blocking calls (sync DB driver, `requests`, `time.sleep`, heavy CPU) inside `async def` endpoints: stalls the event loop under load.
- Background tasks that raise silently; missing timeouts on outbound HTTP calls.
- CORS middleware configuration and middleware ordering changes.

## Alembic and SQLAlchemy
- `op.drop_column`, `op.drop_table`, `op.alter_column` with type change: Data High.
- `downgrade()` empty or `pass`: Reversibility High.
- Autogenerated migrations committed without review (spurious drops of columns or indexes are common).
- Session handling: missing commit/rollback, sessions shared across requests or threads.
- Raw SQL via `text()` with string formatting instead of bound parameters.

## Async and concurrency
- `asyncio.gather` without `return_exceptions` hiding failures; fire-and-forget tasks without references (garbage collected).
- Check-then-insert patterns without a unique constraint (race condition).
- Celery tasks: non-idempotent tasks with `acks_late` or automatic retries cause duplicate effects.

## ML-serving and data-science code
- Model file or version path changed: confirm the artifact exists in the deploy environment and the loader matches the format.
- Preprocessing changed without retraining or re-validation: training/serving skew. Treat as High if predictions feed decisions.
- `torch.load` / `pickle` on files from untrusted locations (unsafe deserialization). Prefer `weights_only=True` or safetensors.
- Changed random seeds, thresholds, or class mappings: silent behavior change with no exception to alert on.
- Missing input validation for tensor shapes or dtypes at the API boundary.
- Loading the model per request instead of once at startup (latency regression), or loading at import time (slow cold start and test failures).
- Heavy new dependencies (CUDA builds, large wheels) bloating images and changing runtime behavior.
